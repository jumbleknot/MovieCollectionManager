# Implementation Plan: Move the App to Expo SDK 58

**Branch**: `087-expo-sdk-58` | **Date**: 2026-11-05 | **Spec**: [spec.md](./spec.md)

**Input**: [spec.md](./spec.md) and the [approach proposal](../../docs/proposals/MCM-Expo-SDK-58-Approach.md)

## Summary

Three pull requests, in order. The first two land on SDK 57, so the risky parts are proven against the app members
use today and can be reverted alone.

| PR | Contents | SDK | Stories |
|---|---|---|---|
| **A: Hosting** | `expo-server` adapter with the scheme fix; a trust-proxy test through the real adapter; a healthcheck that sees pages | 57 | US1, US2 (scenario 4) |
| **B: Gates** | One-instance guard; inline-script allowlist; cold-load budget; browser walk; Android launch check | 57 | US2, control run for US4 |
| **C: SDK 58** | The upgrade: `static` + `apiRoutes`, async routes off, R8 off, Jest 30, Gradle 9.4.1, heap in both CI paths, constitution 2.8.0 | 58 | US3, US4 |

The proposal drew changes 2 and 3 as separate PRs, and this plan merges them into PR B. Under the
[batching rule](../../openwiki/process/pull-request-batching.md), a red build on PR B can be attributed to one gate,
because each gate names its own cause. The healthcheck moves to PR A, because it changes runtime behaviour and PR B
should have none. Turning on R8 and async routes stays out of scope.

Design decisions are in [research.md](./research.md), which also records what this plan found that the proposal did not.

## Delivery

### PR A: Hosting (SDK 57)

- **Design**: [contracts/hosting.md](./contracts/hosting.md), research R1 to R4.
- **Tiers**: `nx test mcm-app`, `nx lint mcm-app`, `nx typecheck mcm-app`, `node --test` for prune and the guard,
  web E2E on the dev container (proves FR-004, because that container is the built image), `app-image-scan`.
- **After deploy**: the operator completes backup consent and starts account deletion through to the sign-in page (SC-001).
  Results are quoted in `tasks.md` on PR B's branch, because PR A has merged by then.
- **Rollback**: revert the PR. The next deploy restores the previous adapter, and `cd-deploy` self-reverts on a
  failed health probe.

### PR B: Gates (SDK 57)

- **Design**: [contracts/web-gates.md](./contracts/web-gates.md), [contracts/android.md](./contracts/android.md),
  research R5 to R10.
- **Label**: none. PR B changes `frontend/`, so `app-ci`'s `mobile` path filter already runs the Android half, and the
  `mobile-e2e` label does not exist on this repository. This is the control run: it proves the instrument on an APK
  expected to work, and it also records the launch check feature 081 left as T028.
- **Proof**: each deliberate defect fails its gate on its first run (SC-005), quoted in `tasks.md`, then is reverted.
- **Rollback**: revert. Nothing in this PR reaches members.

### PR C: SDK 58

- **Start only after** A and B are merged and A's production check has passed.
- **Before the first commit**: the [quiet-lock protocol](../081-major-dependency-upgrades/plan.md) (no open `renovate/`
  PR, not across the Friday window, lock on `main` is the last maintenance result) and M0 to M3 from
  [research.md](./research.md).
- **Order**: the bump and alignment first, so one instance and a clean export are proven before anything is fixed
  around them; then config, then tests, then CI and native, then governance.
- **Label**: `mobile-e2e-full`, which `app-ci.yml` names for an SDK bump. It runs the agent flows and every non-agent
  flow.
- **Tiers**: everything in the [final validation checklist](../../openwiki/invariants/feature-validation-checklist.md),
  with skip counts recorded and zero where the spec says so.
- **After merge**: confirm `prod-apk` on the real path (FR-019), then the 7-day watch in SC-008. A final docs-only PR records this evidence.
- **Rollback**: web through the previous image digest, with no data migration; Android through the previous APK on
  the shelf.
- **Deadline**: if C has not merged by 2026-12-01, renew the `decode-uri-component` entry first.
