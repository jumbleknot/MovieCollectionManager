# ADR-0004 — Wiki Summaries Are Maintained by the Coding Session, Not by a Scheduled Generator

**Status**: Accepted
**Date**: 2026-11-10
**Feature**: [098 — session-maintained wiki summaries](../../specs/098-session-maintained-wiki/spec.md)
**Deciders**: Steven Watson
**Supersedes / relates to**: supersedes **in part** [ADR-0003](ADR-0003-claims-and-fingerprints.md) (its Claims half); [docs/proposals/PRD-SessionMaintainedWiki.md](../proposals/PRD-SessionMaintainedWiki.md); features 043, 044, 078 (US6/US7) and 082; PR #980 (the schedule paused); [wiki-maintenance runbook](../runbooks/wiki-maintenance.md).

---

## 1. Decision

**A derived `openwiki/` summary is refreshed by the coding session that changes its source, in the
same PR, and CI blocks a PR whose summary is stale.**

- **Fingerprint.** Each derived page records `resource-sha256`: the SHA-256 of its single `resource`
  file, after CRLF→LF normalisation. Nothing else is fingerprinted.
- **Check.** The required `okf` check gains rule **V17**. It fails a derived page whose fingerprint
  is missing, malformed or different from its source's, whose source no longer exists, or that still
  carries the retired `sources:`/`verified:` fields.
- **Tool.** `node scripts/wiki-refresh.mjs` lists stale pages (`--stale`), shows the source's change
  since the last record (`--diff`), and records the new fingerprint (`--record`). The
  `wiki-refresh` skill teaches the procedure. It is offline and free.
- **Generator.** openwiki stays, but only as a **manual rebuild of operator-named pages**
  (`wiki-maintain.yml`, required `pages` input). There is no schedule.

## 3. Why the coding session

- **It already has the context.** The session that edits a runbook or a source file has just read
  it and knows what changed. A later generator has to rediscover that from scratch, and paid to do
  it on 265 attempts for 39 pages.
- **It already runs on the subscription.** A refresh costs no API spend (CLAUDE.md: the API key is
  only for the movie assistant and OpenWiki).
- **The check is where the change is.** V17 fails the PR that made the summary stale, naming the
  page. Drift can no longer accumulate on `main` between generator runs.
- **The granularity is honest.** One page, one source file, one hash. openwiki's Claim-level
  staleness marked about 30 pages stale on any day (any file cited by any Claim had changed); the
  page-level test found 12 (research R8).

Accepted risk: a session can record a fingerprint without reading the diff. The skill makes `--diff`
step one, and a fingerprint-only change is visible in review.

## 4. What is retired

- **Claims bookkeeping**, deleted and gitignored: `openwiki/.claims/` (43 sidecars, 4.5 MB),
  `openwiki/.page-manifest.json`, `openwiki/.last-update.json` and `openwiki/.maintenance-state.json`.
  The `sources:` and `verified:` front-matter fields are stripped from every page.
- **Checks**: V16 (Claims durability), V12 (commit-date drift warning, replaced by V17) and G13
  (Claims only on derived pages, which has nothing left to separate).
- **Unattended machinery** in `wiki-maintain.mjs` and its workflow: range planning, the run record
  and marker, backlog, low-effort escalation, cooldowns, drift re-planning, the quiet-trigger and the
  Claims audit, with `wiki-quiet.mjs`, `wiki-escalation.mjs`, `wiki-claims-audit.mjs`,
  `openwiki-claims.mjs`, `openwiki-drift.mjs` and their tests.
- **Two directory resources become canonical pages**: `process/spec-driven-development.md` (was
  `specs/`) and `architecture/data-model.md` (was `backend/mc-service/src/domain/`). A derived page
  summarises exactly one file.

**Supersession of ADR-0003.** ADR-0003 held that Claims (on derived pages) and protected-passage
fingerprints (on authoritative pages) are complements. Its **Claims half is superseded**: derived
pages now carry a source fingerprint, not Claims. Its **fingerprint half stands unchanged**:
`openwiki/protected.yaml` still guards the authoritative pages (G5–G7).

---

## 5. The writer policy

`openwiki/policy.yaml`'s `actor` may now be a list. `openwiki/**` becomes `actor: [agent, generator]`:
a session writes routinely, and the generator writes on a manual rebuild. G3's meaning is kept:
`generator` may still write nowhere outside `openwiki/`. A new rule, **G14**, fails a derived page
whose `resource` is a directory or a file that Renovate or CD rewrites, so that no bot change can
make a page stale with no session there to refresh it.

---

## 6. Revisit when

- **Scoring says so.** A follow-up item scores SC-001/SC-003/SC-004 four weeks after the switch-over,
  by replaying V17 across first-parent merges. Revisit if refreshes are routinely fingerprint-only
  where the diff changed what the page says.
- **The generator becomes cheap and reliable** enough that an unattended run lands what it is asked
  for at a cost that does not matter.
- **A derived page's source becomes something a bot rewrites** and G14 cannot be satisfied by
  re-pointing it.
- **`backend/mc-service/src/domain/` becomes active again** (0 commits in the three months before this
  decision). Then re-point `architecture/data-model.md` at one file and record it.
